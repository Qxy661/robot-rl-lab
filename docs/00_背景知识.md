# 00 · 读这份代码需要的最小背景

这一章不打算教你 Python，而是**只讲读懂本项目代码所需要的那部分**。编程语言的书
动辄几百页，其中九成的内容你在这个项目里碰不到。与其从头学一遍，不如先掌握这
一成，然后对着真实代码补。

读完本章，你应该能看懂 `robotrl/assets/spec.py` 和 `robotrl/contracts.py` 这两个
文件——它们是整个项目的接口定义，也是最好的练手材料。

## 变量就是给数据起的名字

```python
n_dof = 15
name = "g1"
kp = 100.0
is_biped = True
```

`=` 不是数学里的"等于"，而是"把右边这个东西存起来，名字叫左边"。之后每次用到
`n_dof`，拿到的就是 15。

四种最基本的数据：整数（`15`）、小数（`100.0`）、字符串（`"g1"`）、布尔值
（`True` / `False`）。看着简单，但有一件事要提前记住：**`100` 和 `100.0` 是两种
不同的东西**。前者是整数，后者是小数。在机器人控制里这通常无所谓，但在数组运算
里会引发类型不一致的报错，所以项目里的物理量一律写成 `100.0` 这种带小数点的形式。

## 列表、元组、字典

三种装东西的容器，区别在于"能不能改"和"有没有名字"。

```python
joints = ["hip", "knee", "ankle"]        # 列表：能增删改
joints[0]                               # "hip"，从 0 开始数
joints.append("waist")                   # 加一个

angles = (-0.1, 0.3, -0.2)               # 元组：定下来就不能改
```

列表和元组长得很像，区别是元组一旦创建就不能修改。你可能会想"不能改有什么好的"，
但在这个项目里这一点很重要。机器人的关节顺序如果被代码某处意外改动了，训练好的
模型就跟它对不上了，而且这种错误不会报错，只会让训练悄悄失败。用元组，等于让
Python 帮你保证"这份定义不会被改动"。

```python
spec = {"name": "g1", "n_dof": 15}       # 字典：用名字取值
spec["name"]                              # "g1"
```

字典适合"键值对应"的场景，比如配置项、奖励权重表。

## 函数：把一段操作打包

```python
def scale_action(action, scale):
    return action * scale
```

`def` 开始一个函数定义，括号里是输入（参数），`return` 是输出。函数的意义是
**给一段操作起个名字**，这样别处用的时候不必关心里面怎么实现的。

有两种参数写法值得注意：

```python
def get_spec(name: str) -> RobotSpec:      # 冒号后面是类型注解，箭头是返回值类型
    ...

def make(name, *, config=None, **kwargs):  # * 后面的参数必须用名字传
    ...
```

类型注解（`name: str`）是给人看的，写错了 Python 也不会拦你，但它让代码可读性
提高很多，编辑器还能据此提示。`*` 之后的参数必须写成 `robot="g1"` 这种带名字的
形式，不能只传位置——参数一多，这样能防止传错顺序。

函数可以返回多个值，实际上是返回了一个元组：

```python
obs, info = env.reset()      # reset 返回 (观测, 信息)
```

## 类：把数据和操作打包在一起

函数打包操作，类打包"数据 + 操作"。本项目里到处都是类，比如 `RobotSpec`：

```python
spec = get_spec("g1")        # 造一个实例
spec.n_dof                   # 读它的属性，15
```

`class` 定义一个类，类里面叫 `self` 的东西指的是"这个实例自己"：

```python
class BaseEnv:
    def __init__(self, spec):
        self.spec = spec          # 存起来，之后别的方法都能用

    def reset(self):
        return self._observe()    # self._observe() 调用自己的另一个方法
```

`__init__` 是构造时自动执行的函数，用来做初始化。名字前后带双下划线的方法
（`__init__`、`__repr__`）是 Python 的特殊约定，你不用主动调用它们。

方法名前带一个下划线（`_observe`）是"内部使用"的约定——不是强制规定，只是告诉
读代码的人"这是实现细节，外面别直接调"。

**继承**是类的一个重要机制。本项目的环境层就靠它：

```python
class BaseEnv:            # 基类：定义有哪些方法
    def step(self): ...

class MujocoEnv(BaseEnv): # 子类：继承基类，填具体实现
    def step(self): ...
```

`BaseEnv` 规定了环境必须有哪几件事，`MujocoEnv` 负责具体怎么做。好处是上层代码
只需要知道 `BaseEnv` 的约定，换一种环境实现不用改上层。

## dataclass：专用来装数据的类

```python
from dataclasses import dataclass

@dataclass
class Obs:
    policy: np.ndarray
    critic: np.ndarray
```

`@dataclass` 是装饰器，加了它之后 Python 会自动生成初始化函数，不用手写
`def __init__(self, policy, critic): self.policy = policy; ...`。定义一个
"只有数据、没有复杂行为"的类时用它最省事。

加 `frozen=True` 就变成不可修改的：

```python
@dataclass(frozen=True)
class RobotSpec:
    ...
```

`RobotSpec` 用了这个。它的含义是：形态定义一旦建立就不允许再改。这跟前面讲
元组是同一个道理——防止训练中途有人顺手改掉关节数，导致难以排查的错误。

## NumPy：机器人代码的通用语言

NumPy 提供 `ndarray`，一个可以整体参与运算的数组。本项目的观测、动作、关节
角度全是 ndarray。

```python
import numpy as np

q = np.array([0.1, 0.2, -0.3])      # 三个关节的角度
q * 2                                # [0.2, 0.4, -0.6]，整体乘 2
q + np.array([0.1, 0.1, 0.1])       # 逐元素相加
np.linalg.norm(q)                    # 长度（模）
```

用数组而不是列表，关键在于**整体运算**。15 个关节的力矩计算写成一行
`kp * (target - q) - kd * qd` 就够了，不用写循环。这类代码在 CPU 上由底层
一次算完，比循环快得多——而且写起来更接近数学公式本身。

### 形状：数组的维度

数组的"形状"（shape）是调试时最该盯的东西。

```python
a.shape            # (15,)      一维，15 个数
b.shape            # (64, 15)   二维，64 行 15 列
```

本项目里第二维通常是"一次处理多少条数据"：单个观测是 `(15,)`，64 个环境的
批量观测是 `(64, 15)`。写成 `(..., 15)` 表示"最后一维是 15，前面有几维都行"，
这样同一段代码能处理单个也能处理批量。

观测量、动作量、奖励量的形状必须严格对上，而形状不匹配的报错信息常常不好懂。
养成习惯：怀疑代码有问题时，先把相关数组的 shape 打出来。

### 索引与切片

```python
q[0]            # 第 0 个元素
q[2:5]          # 第 2、3、4 个，含头不含尾
q[:, 0:3]       # 二维数组：所有行的前 3 列
```

`2:5` 这种写法叫切片，注意**不含结尾的 5**。项目里读观测的某一段就靠它，
比如"取 cmd 这一段"就是取 3 个元素。

### 广播

形状不同的数组做运算时，NumPy 会自动把小的那个"撑开"：

```python
kp = np.array([100.0, 150.0, 40.0])   # 形状 (3,)
error = np.array([[0.1, 0.2, 0.3],    # 形状 (2, 3)
                  [0.4, 0.5, 0.6]])
kp * error                             # kp 被自动当成两行，逐行相乘
```

广播省掉了手写循环，但也会掩盖形状错误——写错了它可能不报错，只是算出来的东西
不对。对不确定的地方，显式把形状写出来。

## 类型注解与静态检查

```python
def make_obs_contract(n_dof: int) -> ObsContract:
```

冒号后是参数类型，箭头后是返回值类型。注解不参与运行，但有两个实际好处：
编辑器能提前发现错误，读代码的人不用猜这个参数该传什么。

项目里还会看到 `int | None` 这种写法，意思是"整数或空"。`None` 表示"没有值"。

## 读懂一个陌生文件的方法

最后给一套可操作的顺序，比逐行硬啃有效得多：

1. 读文件开头的 **docstring**（三引号包起来的那段）。本项目每个文件开头都写了
   这个文件解决什么问题，读完能省掉大量猜测。
2. 看有哪些 `class` 和 `def`，先不看实现。这一步建立"这个文件提供了什么"的轮廓。
3. 找到你要用的那个函数或类，读它的**参数和返回值**，以及 docstring 里对参数
   的说明。
4. 这时候再进实现。实现里看不懂的表达式，回来查这一章对应的部分。

对着 `spec.py` 试一遍：开头讲了两个设计要点，然后是一个 `Morphology` 类
（枚举，一组固定取值）、一个 `RobotSpec` 数据类（字段和校验）、最后是注册表
的三个函数。轮廓清楚了，细节就好啃了。
